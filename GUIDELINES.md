# Gallery guidelines

The gallery is a small, curated set of scripts that people can read, trust
and learn from. A maintainer reviews every script before it is published and
can hide any script at any time.

## What a script must be

- **Honest.** It does what its name and description say, and nothing else.
- **Readable.** One plain JavaScript file that a reviewer can read from top to
  bottom. Not minified, not obfuscated, not generated by a bundler.
- **Self-contained.** All the code is in `script.js`. It never downloads code
  to run and never builds code from strings (`eval`, `new Function`).
- **Minimal in its permissions.** It declares exactly the permissions it uses,
  and uses them only for its stated purpose.
- **Yours to share.** You wrote it, or its license allows you to publish it
  under the license you name.

## Permissions and privacy

- Declare every permission. Undeclared use is rejected automatically.
- Say in the description or README which hosts a script contacts and what it
  sends them.
- Send personal data (location, calendar, reminders, clipboard) off the
  device only when that is the obvious point of the script, and only to the
  service the description names.
- No analytics, tracking, advertising identifiers or fingerprinting.
- No collecting data for the author. A script works for the person running it.
- If a script needs an API key, the person running it supplies their own. Never
  ship a key.

## What gets rejected

- Anything that hides what it does: obfuscation, encoded payloads, remote code.
- Scripts that contact hosts unrelated to their purpose.
- Objectionable content in the name, description, icon, README or output:
  hate, harassment, sexual content, graphic violence, or content that targets
  a person or group.
- Illegal content or uses; scraping that breaks a service's terms; attempts to
  access accounts or systems without authorization.
- Impersonation of a company, product or person; misleading names or icons;
  use of trademarks or logos you have no right to.
- Gambling, medical, financial or safety claims the script cannot stand behind.
- Spam: near-duplicates, placeholder scripts, scripts that exist to promote
  something.
- Scripts that try to change what the app is: app stores, script loaders,
  anything that fetches and runs other scripts.

Maintainers may decline a submission that follows the letter of these rules
but not their purpose. We will say why.

## Icons, names and descriptions

- Icon: a square PNG, 256–1024 px, at most 200 KB. No text-heavy images, no
  third-party logos.
- Name: at most 50 characters. Describe the script; do not shout or stuff
  keywords.
- Description: at most 280 characters, in plain language.

## Reports and takedowns

Anyone can report a script:

- in the app, with **Report script** on the script's page, or
- by opening a [report issue](../../issues/new?template=report-script.yml), or
- privately, by email (see [Contact](#contact)).

A maintainer looks at every report, normally within two working days. If the
script breaks these guidelines, the maintainer sets `"status": "hidden"` in
its `meta.json`. On the next publish, minutes later, the script disappears
from the gallery in every copy of the app and can no longer be installed. No
app update is involved. People who already installed it keep their copy,
which is theirs to read, edit or delete, and the app tells them the script
was withdrawn.

Authors are told why in the report issue or the original pull request, and
can submit a fixed version. Repeated or deliberate violations lead to all of
an author's scripts being hidden and further submissions being declined.

In the app, anyone can also choose **Hide scripts from this author** to stop
seeing an author's scripts on their own device.

## Copyright

If you believe a script infringes your copyright, email the contact address
with the script id, the work concerned and your contact details. We hide the
script while we look into it.
